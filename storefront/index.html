EXPERIENCE · STOREFRONT

Order the outcome.
Not the ingredients.

InfrastructureProductWorks Storefront is a customer-hosted ordering experience for governed infrastructure products. Developers choose a product and provide bounded business intent instead of learning the provider topology, Terraform modules, Crossplane internals, IAM documents and implementation mechanics behind it.

INTERACTIVE DEMO · SYNTHETIC ONLY · NO PRODUCTION ORDERS

YOU PROBABLY NEED STOREFRONT IF...

Your “self-service” portal still makes developers design infrastructure.

TICKET QUEUES

Routine requests still begin with tickets and handoffs.

Teams wait for platform engineers to interpret common requests that should already exist as supported products.

TOO MANY CHOICES

Developers must understand provider internals.

Request forms expose networking, IAM, modules, regions and topology instead of asking for the business outcome the team actually needs.

PORTAL FRAGMENTATION

Every portal invents its own infrastructure vocabulary.

Storefront and its Backstage adapter preserve one InfrastructureProductOrder contract so the experience can vary without redefining the product.

AUTHORITY CREEP

Self-service is confused with direct cloud privilege.

Storefront captures and validates bounded intent, then stops at governed review rather than granting approval or provisioning authority.

Storefront is the remedy: give developers a simple product catalog and guided order flow while keeping provider complexity, privileged access and implementation decisions behind the platform boundary.

THE PROBLEM

Self-service is not the same thing as a product.

A portal that exposes dozens of cloud primitives can still push architecture decisions onto every application team. Storefront takes the opposite position: define a small number of durable infrastructure products, give each one a stable contract, and let the platform own how approved ingredients become the requested outcome.

WHAT YOU ACTUALLY GET

A simple way to request governed infrastructure products.

Storefront gives developers a product-ordering experience instead of a form full of provider internals. The output is a bounded, reviewable product order that downstream systems can verify.

CATALOG

Current demo plus planned products

Teams can use the current Cloud Foundation Environment demo and see planned outcomes such as Managed Interconnect, Data Platform Environment and Kubernetes Platform without starting from raw AWS, Azure or GCP resources.

GUIDED ORDER

Only the choices the product supports

The order form captures business and product intent using closed, supported values so developers do not have to design networking, IAM, modules or provider topology themselves.

VALIDATION

A validated product order

Required fields and contract rules are checked before handoff, catching unsupported values or incomplete requests before they enter the governed review path.

HANDOFF

A digest-bound order record

The selected product, inputs and handoff evidence can be cryptographically bound so downstream consumers can detect if the reviewed order was changed.

PORTAL CHOICE

Standalone or Backstage experience

Organizations can use the canonical Storefront experience or a Backstage adapter while keeping the same underlying InfrastructureProductOrder contract.

STATUS

A visible path into governed review

Users can see that a valid request has moved into the next governed step without Storefront pretending that validation means approval or provisioning.

Storefront is the front door. It packages intent cleanly; it does not approve the order, create cloud credentials or provision infrastructure on its own.

The app stops at governed review.

BACKSTAGE ADAPTER

Already use Backstage? Keep it.

You do not have to replace an established internal developer portal to use the same governed infrastructure-product model. Infrastructure Product Works supports two experience surfaces over one order contract.

OPTION 1 · STANDALONE

Use the Infrastructure Product Works Storefront.

Choose this when you want the ready-made customer-hosted ordering application. It is the canonical IPW experience and owns the product catalog, guided order flow, local status and handoff inspection experience.

Best fit: organizations that do not already have Backstage, or teams that want Storefront without making an internal developer portal a prerequisite.

OR
OPTION 2 · BACKSTAGE

Install the Storefront adapter in your existing portal.

The Backstage adapter packages the same Cloud Foundation Environment ordering experience as a Backstage Software Template. Your developers stay in the portal they already use while submitting the same governed order contract.

Best fit: organizations already operating Backstage as their internal developer portal and wanting infrastructure products to appear alongside their existing software catalog and templates.

SAME CONTRACT

One InfrastructureProductOrder

Standalone and Backstage both emit the same closed order contract. Switching the user experience does not redefine the infrastructure product.

OPTIONAL GITHUB HANDOFF

PR into your review repository

When a customer intentionally configures an authorized GitHub integration, the adapter can use Backstage's standard pull-request publishing action to place the order into a customer-owned review repository.

SEPARATE VERSION

Adapter evolves independently

The Backstage distribution is independently versioned, so portal integration can change without forcing the standalone Storefront or the product contract to change with it.

NO HIDDEN AUTHORITY

Still not a control plane

The adapter can collect and publish an order. It does not approve infrastructure, hold privileged cloud credentials or provision AWS, Azure, GCP, Kubernetes or Crossplane resources.

The simple rule

If you need a ready-made portal, use Storefront. If your company already has Backstage, use the adapter. Either way, the developer creates the same governed product order and enters the same downstream review process.

COMMERCIAL BOUNDARY

Entitlement controls access. Governance controls infrastructure.

PUBLIC

Interactive demo

Synthetic product selection and ordering experience for evaluation. No real customer execution or production authority.

CUSTOMER

Authenticated workspace

Future real workflows can require organization identity, entitlement, retained evidence and governed integrations.

ENTERPRISE

Customer-controlled deployment

Enterprise licensing can support SSO, restricted-network deployment, support and negotiated operating boundaries.

SEPARATION

Payment is not permission

A subscription or license permits use of the product. It never bypasses Guard, human authorization, Assurance or downstream reconciliation controls.

ENGINEERING PROOF

The contract is the product boundary.

CONTRACT

Closed order values

Consumer intent is constrained to the supported product vocabulary instead of accepting arbitrary provider configuration.

HANDOFF

Digest-bound evidence

The order can be bound to an inert handoff and verification record so downstream consumers can detect mutation.

ADOPTION

Backstage without lock-in

The Backstage surface is an adapter to the same contract, not a requirement that every customer adopt the same portal technology.

AUTHORITY

Review before action

A valid order enters governed review. The Storefront does not acquire approval, cloud or reconciliation authority merely because validation passed.
