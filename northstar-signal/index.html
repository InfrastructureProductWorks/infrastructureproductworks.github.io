THE PRODUCT SYSTEM

Northstar knows more than the OKR.

A sound cloud-product decision needs organizational context, existing capability evidence, investment context, bounded authority and a path into the systems teams already use. Northstar is designed to keep those pieces connected without turning any one signal into hidden decision authority.

ORGANIZATIONAL PROFILE

Know whose outcome this is.

A Division Registry and scoped organizational profile identify the accountable business context, leadership scope, approved systems, decision roles and evidence expectations behind the outcome. Profile changes require explicit versioning and renewed review rather than silently inheriting prior approval.

CAPABILITY AWARENESS

Reuse before build.

Northstar can bring existing products, capabilities, constraints and evidence into the decision so leaders can compare reuse, build, phase, defer or redirect instead of assuming every new need requires new infrastructure.

INVESTMENT + TCO

Ask whether the investment makes sense.

Investment context is intended to combine expected cost, lifecycle/TCO assumptions, reuse opportunity, duplication risk and expected benefit. The point is not merely “Can we build it?” but “Should we, what will it cost over time, and did the value show up?”

EVIDENCE + CONFIDENCE

Show why the recommendation exists.

Evidence retains source, provenance, confidence and freshness so capability, talent, assessment or repository signals can inform a decision without becoming an opaque score or autonomous verdict.

ADAPTER LAYER

Keep the tools teams already use.

Bounded adapters are designed for Jira, Azure DevOps, GitHub Issues and future enterprise integrations such as ServiceNow. Northstar hands off authorized work while preventing downstream backlog state from rewriting the upstream decision.

PORTFOLIO INTELLIGENCE

See decisions in context.

Leadership views can connect objectives, Key Results, investments, reusable capabilities, dependencies, delivery signals, evidence confidence and measured outcomes at the organizational scope the approved profile permits.

CONTEXT BEFORE DECISIONProfile + Strategy + Existing Capabilities + Investment/TCO + Evidence → Decision

Northstar is meant to assemble decision context, not manufacture authority from data. Human accountability and explicit authorization remain separate from recommendations, cost models and AI-generated proposals.

FROM DECISION TO EXECUTION

AI can help compose the work. It cannot quietly advance it.

Northstar uses the same bounded-authoring pattern on both sides of the leadership decision: Composite AI can help leaders draft OKRs and help management draft Epics, while deterministic validation and accountable humans control acceptance.

LEADERSHIP COMPOSER

Intent → proposed OKRs

Composite AI proposes outcome language and measurable Key Results. Northstar validates structure. The accountable leader accepts, edits or rejects.

EXACT AUTHORIZATION

Decision → CAR

Each eligible item receives its own bounded Capability Authorization Record. Multi-item review never merges authority, and a CAR does not grant funding, procurement, risk, deployment or provisioning authority.

MANAGEMENT COMPOSER

CAR → proposed Epics

Management receives the current CAR, scope, constraints, catalog context and existing work. Composite AI proposes Epics; reuse/equivalence and deterministic checks run before explicit management acceptance.

BOUNDED HANDOFF

Accepted work → backlog

Only an accepted, current package can produce the bounded handoff package. Changing the CAR, package or target invalidates stale acceptance rather than letting old approval travel forward.

OUTCOME + INVESTMENT FEEDBACK

Delivery tells Northstar what happened. Evidence tells leadership whether it mattered.

Backlog completion, deployment and product release are execution signals. Northstar keeps them separate from authoritative outcome evidence, then brings cost, benefit and delivery context back into the next investment decision.

DELIVERY SIGNAL

Did we finish the authorized work?

Adapters can report bounded execution state from the team's existing system without allowing ticket status to declare the Key Result achieved.

OUTCOME SIGNAL

Did the intended result occur?

The named evidence source measures the Key Result independently from delivery completion so activity cannot masquerade as benefit.

INVESTMENT SIGNAL

Was it worth continuing?

Expected TCO and benefit assumptions can be compared with observed cost and outcome evidence to inform reuse, expansion, correction, retirement or the next planning cycle.

Northstar closes the management loop.

Strategy and profile context shape the decision; authorization shapes the work; adapters carry bounded execution signals; evidence and investment results return to leadership for the next decision.

WHO IT SERVES
